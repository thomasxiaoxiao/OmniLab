# Open-source decision runtime

The user requested real decision-only reasoning in a tightly bounded environment.
The default is **AnyJev 0.2.0 + Qwen3-4B-Instruct-2507 (4-bit) + MLX-LM 0.32.0**.
No decision is generated by a scripted research role. Test doubles live in `tests/`.

## Architecture decision

| Candidate | Fit for this implementation | Decision |
| --- | --- | --- |
| [AnyJev](https://github.com/nokia-applied-research/AnyJev) | Open-source closed-question decisions from label logits; L0 works without training labels | Selected; small custom MLX logits adapter for the available Apple Silicon Mac |
| [LLM2Jev](https://github.com/Yinsongxu/LLM2Jev) | Open-source Jev-inspired decision framework | Considered; not installed or benchmarked in this project |
| [litjev](https://github.com/zhengxuyu/litjev) | Open-source Jev-inspired implementation | Considered; not installed or benchmarked in this project |
| Existing Omnigent integration | Real model sessions, but schema-constrained generated JSON | Preserved as optional CLI integration; not the decision-only UI backend |

The choice minimizes new infrastructure: one local model, no account or hosted
service, and no training dataset prerequisite. MLX uses this Mac's unified memory.
This is not a claim that AnyJev reproduces proprietary Jev internals or that its
scores are calibrated. Hardware and scientific quality remain separate checks.

The model is [mlx-community/Qwen3-4B-Instruct-2507-4bit](https://huggingface.co/mlx-community/Qwen3-4B-Instruct-2507-4bit),
revision `50d427756c6b1b2fe0c0a10f67fbda1fc8e82c1b`, converted from Qwen's instruct
model. The setup command downloads only data/tokenizer/template files, never
remote Python. It records local SHA-256 checksums and verifies them before each
run. Checksums detect local changes, not a malicious writer replacing the manifest.

## Decision contract

1. Retrieval scans all supplied source pages and ranks exact, overlapping spans.
   Sentence starts preserve context; lexical IDF and generic future-work terms
   affect candidate retrieval only. The model chooses whether the evidence
   supports an executable direction. It may choose unsupported or uncertain.
2. Every resulting proposal receives a separate source-entailment judgment, then
   a model accept/reject/defer feasibility judgment when supported. A
   separate closed question ranks accepted proposals for feasibility, control
   comparability and interpretability within the declared budget. The selected
   proposal is persisted; there is no first-accepted fallback in AnyJev mode.
3. Literature assessment, authorization of the selected experiment and review of
   measured results are separate closed model questions. The model has no shell,
   network tool, editable thresholds, or arbitrary next-state interface.
4. The application executes only the reviewed recipe after the baseline gate.
   It independently checks numerical validity, intervals, source quotations,
   schemas and the novelty gate. Model scores cannot bypass these checks.

Available experiments remain the implemented random-Manhattan, site-percolation
and resistor-diode recipes. This bounds the action space; it does not preselect
the model's answer. Titles and explanations are mechanical renderings of the
recipe and selected option, not invented model rationales.

AnyJev reads the next-token logits for option labels and combines every cyclic
option ordering at L0 (`prior="none"`). There is no autoregressive generation:
`generated_tokens` is zero. Full option weights are saved. No labeled calibration
set has been fit; these weights are not probabilities of scientific correctness.
If the two highest weights differ by less than 0.05, execution stops for review.
That margin is a declared operational ambiguity rule, not a statistical guarantee.

## Limits and failure handling

- Each question has 2–8 options and at most 4,096 input tokens per permutation.
  Oversized context is rejected, never silently truncated.
- Each run has a finite role budget and at most 32 decision calls by default
  (hard maximum 64). Every decision uses at most eight model prefills. Input token
  counts and prefills are logged; no automatic retries spend additional calls.
- Inference runs in a killable subprocess with a per-question timeout and shared
  run deadline. It is closed on success, abstention, timeout and errors. This is a
  lifecycle boundary, not an OS security sandbox.
- Missing runtime/weights, invalid distributions, ambiguity and model stop choices
  preserve partial artifacts. None of them invokes a scripted fallback.
- Source text is untrusted data. Fixed options and code gates bound action even if
  hostile text influences the model; prompt instructions alone are not a security guarantee.

`decisions/NN-question.json` records state, allowed options, input hash, selected
answer, distribution, model identity, prompt version, inference usage, timing and
ambiguity check. The UI verifies the audit against role outputs and downstream
plans. Historical scripted runs remain visibly labeled historical artifacts.

## Run and inspect

```bash
uv sync --locked
uv run --locked research prepare-model
uv run --locked research fetch
uv run --locked research run --config examples/percolation/decisions.json \
  --output output/research/my-decision-run
uv run --locked research verify output/research/my-decision-run
npm run dev
```

On other hosts the UI and tests can run, but this local model adapter requires
Apple Silicon and MLX. Set `RESEARCH_DECISION_MODEL_DIR` to a stable absolute
directory when launching from a PM2 release. A readiness indicator only checks
installed packages and manifest presence; successful inference is recorded by a run.

Model-dependent behavior is tested with clearly labeled protocol doubles. These
tests verify enforcement, not model quality. Live validation must be demonstrated
by a saved run with real prefills and model scores. No scientific novelty is
established by the runtime, a passing unit test, or one paper alone.
